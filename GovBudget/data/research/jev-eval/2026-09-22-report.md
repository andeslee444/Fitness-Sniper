# Jev test for Fiscal Receipts — September 22, 2026

**Result:** Jev is promising for program-identity matching and evidence-backed claim screening. Program lineage needs precise questions and review; prompt changes improved recall while introducing false positives.

## What actually ran

- Model: `jev-1.13.0`, called directly at TypeSafe's official API.
- **155 distinct baseline cases**, then **71 repeated lineage cases** with revised questions, plus one connectivity probe: **227 API calls**.
- **284,811 input tokens**; estimated inference charge **$0.011962** (about 1.2 US cents).
- Median observed end-to-end response: **0.412 seconds**; p95 **0.532 seconds**. Four concurrent requests, from this Mac; timing includes network overhead and is not a service-level guarantee.
- No API errors. Choice, Noul, and Score response types all exercised. Only Choice labels were scored against expected decisions; scores and yes/no probabilities were diagnostics.
- Price basis: [$0.042 per million input tokens; output free](https://docs.typesafe.ai/models). This estimates usage, not an account invoice.

## Frozen baseline results

| Test group | Agreement with reference | Interpretation |
|---|---:|---|
| Existing GAO-to-program adjudications | 63/63 | 62 positive matches and one negative; predominantly easy positive cases, not a balanced benchmark. |
| Constructed wrong-program/variant/service controls | 8/8 | Includes Sentinel missile versus radar, SDB-related distinctions, and different aircraft or space systems. |
| Constructed claims against actual F-15EX source evidence | 13/13 | Supported claims, direct contradictions, unestablished outcomes, and request-versus-payment distinctions. |
| Existing lineage adjudications | 42/53 | All 11 disagreements were rejected positive reference links; one rejection had 0.94 reported confidence. |
| Constructed reversed transfer directions | 12/12 | Correctly rejected all reversed directions in the baseline. |
| Missing transfer evidence | 6/6 | Returned insufficient rather than guessing. |

These are agreement counts for supplied packets, not production accuracy estimates. The 53 lineage records include 49 accepted links, 2 rejected links, and 2 semantically true links refused for publication. The latter two are scored as true here; publication rules are untouched.

## Follow-up: more specific lineage questions

After inspecting baseline disagreements, repeated the same 71 lineage cases with clearer criteria and pair-specific questions about (1) whether a directed movement is described and (2) whether it is explicitly a one-time adjustment. No state, expected label, or source excerpt changed. This is exploratory tuning on known cases, **not held-out validation**.

- Existing lineage agreement improved to **51/53**.
- Reversed-direction controls declined to **11/12**.
- Missing-evidence controls remained **6/6**.
- The revised questions introduced **two false positive links**: a genuine one-time Space Force funding adjustment misread as lineage (confidence 0.48), and a reversed Air Force/Space Force relationship (confidence 0.31).
- The remaining false negative concerned an implicit source program/project (confidence 0.40).
- The temporary-adjustment diagnostic assigned 0.89 probability to the one-time restriction even while the main Choice accepted that same relationship. Typed questions can disagree; application rules must handle that.

A descriptive 0.90 confidence cutoff would route all three refined-run errors to review, but confidence alone is not validated here: the baseline already contained a wrong decision with 0.94 confidence. An exploratory stricter rule combining Choice confidence and both Noul answers would decide 45/71 cases, agree on all 45, and route 26 to review. That observation is in-sample, not a deployable threshold.

## Independent fixture audit and limits

An independent agent reviewed the frozen case labels **without seeing results**. It found no label contamination in request state. Reversed directions, absent evidence, and GAO controls were defensible.

Four lineage positive references describe single-year funding transfers without clearly establishing the baseline rubric's extra requirement of an enduring activity move. Their disagreement is partly rubric-sensitive: `lineage_8964388ad52bbbd9_2`, `lineage_9fb59fbc6b9ef9bf_4`, `lineage_5f9b8739fffc3798_7`, `lineage_157c7b5c19b116da_20`. Original scores are preserved.

One constructed claim, `claim_request_1`, says a request source establishes money was paid. `not_established` is our reference, but `contradicted` could also be defended as a false attribution to that source. Future holdout wording should assert the outcome directly.

Twenty-two GAO cases have report titles/subject/index metadata rather than full report body. Those test program identity, **not whether every report finding applies to a budget line**. The remaining 41 seeded GAO cases and 8 constructed GAO controls have parsed assessment descriptions. Repeated program/report pairs and controls are correlated observations. The API received public source evidence plus questions, without local expected labels or curator notes.

## Product recommendation

1. **First pilot: Receipts Check inside editorial review.** Flag unsupported claims, request-as-spending language, and mismatched program variants; retain the source excerpt beside every flag. Keep numerical validation in code.
2. **Next: candidate matching for thematic exploration and oversight links.** These checks were consistently strong in this bounded set, but need a larger set of difficult negative matches.
3. **What actually changed: use Jev to propose and prioritize explanations for review.** The transfer test shows enough semantic sensitivity to be useful, and enough prompt sensitivity to preserve existing human ratification.

Before automatic publication, freeze the rubric and evaluate fresh human-reviewed cases, with false-support rate, abstention/review volume, and confidence behavior reported separately. Neither these results nor typed outputs prove evidence correctness.
