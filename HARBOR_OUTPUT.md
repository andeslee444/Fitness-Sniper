## Research Findings

### 1. MindBody Architecture
MindBody has **two** booking interfaces:
- **Modern Cart System** (`cart.mindbodyonline.com/sites/{siteId}`) — used by Dogpound and most current studios via Healcode widgets
- **Classic ASP** (`clients.mindbodyonline.com/ASP/su1.asp?studioid={id}`) — older studios, server-rendered HTML

### 2. Dogpound Details

| Bot protection | None detected |

### 3. Booking Flow (Modern Cart)
1. Schedule loaded via Healcode widget → classes rendered with `add_booking` links
2. Each class link: `cart.mindbodyonline.com/sites/57707/cart/add_booking?item[mbo_id]=53627&item[type]=Class&...`
3. Login via `cart.mindbodyonline.com/sites/57707/client`
4. Checkout to confirm booking

### 4. Official API
- MindBody Public API v6 exists at `api.mindbodyonline.com/public/v6/`
- **Not practical** — requires studio cooperation to activate API key
- Best for: `GET /class/classes`, `POST /class/addclienttoclass`, `POST /class/addclienttowaitlist`
- npm package: `mindbody-api-v6` (TypeScript, by SplitPass)

### 5. Existing Open Source

| shane-jeon/WaitlistWarrior | Python + Selenium + Twilio alerts |

### 6. Anti-Bot Assessment
- **Minimal** — classic ASP has no anti-automation
- Modern cart uses jQuery + standard forms
- No reCAPTCHA, Cloudflare, or fingerprinting detected
- Simple session cookies for auth

## Architecture

```
MindBodyAdapter (modern)
├── login() → cart.mindbodyonline.com/sites/{id}/client
├── getClasses() → Healcode widget print view + add_booking URLs
├── bookClass() → Add to cart → checkout
└── snipeClass() → Poll + auto-book when available

MindBodyClassicAdapter (legacy)  
├── login() → clients.mindbodyonline.com #su1UserName/#su1Password
├── bookClass() → Schedule tab → sign-up → #SubmitEnroll2
```
