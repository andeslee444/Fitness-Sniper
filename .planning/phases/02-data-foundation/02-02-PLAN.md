<task type="auto">
  <name>Task 2: Build GET /api/calendar route with UNION ALL query</name>
  <files>web/src/app/api/calendar/route.ts</files>
  <action>
Create `web/src/app/api/calendar/route.ts` with a `GET` handler that:

1. **Auth:** Call `getSession()`. Return 401 `{ error: 'Unauthorized' }` if null.

2. **Param validation:** Read `weekStart` from `request.url` searchParams. Validate with `/^\d{4}-\d{2}-\d{2}$/` regex. Return 400 `{ error: 'weekStart query parameter is required (YYYY-MM-DD)' }` if missing or invalid.

3. **SQL query:** Execute the UNION ALL query with two parameters: `[user.sub, weekStart]`.

The SQL has four branches joined by UNION ALL:

**Branch 1 — booking_history (booked/failed):**
- Select from `booking_history` where `user_id = $1` and `class_date` is within the 7-day window.
- `event_type`: `CASE status WHEN 'booked' THEN 'booked' ELSE 'failed' END`
- `source`: `'history'`
- `meta`: `jsonb_build_object('spot', spot, 'message', message)`

**Branch 2 — booking_jobs (pending):**
- Select from `booking_jobs bj LEFT JOIN snipe_targets t ON t.id = bj.target_id`
- Filter: `bj.user_id = $1`, `bj.status IN ('pending', 'claimed', 'running')`, date within window.
- Use `COALESCE(bj.class_datetime, bj.scheduled_for)` for date/time, converted `AT TIME ZONE 'America/New_York'`.
- Time format: `to_char(..., 'FMHH12:MI AM')`.
- `event_type`: `'pending'`
- `source`: `'job'`
- `meta`: `jsonb_build_object('scheduled_for', bj.scheduled_for, 'class_datetime', bj.class_datetime, 'job_status', bj.status)`
- Use `LEFT JOIN` for `studio_slug` (not subquery — per research anti-patterns section).

**Branch 3 — snipe_targets recurring:**
- Select from `snipe_targets st` where `user_id = $1`, `enabled = true`, `target_type = 'recurring'`, `day_of_week IS NOT NULL`.
- Compute `event_date` by expanding `day_of_week` into the 7-day window:
  ```sql
  (week_start + ((st.day_of_week - EXTRACT(DOW FROM week_start)::int + 7) % 7) * INTERVAL '1 day')::date::text
  ```
- `event_time`: `st.time`
- `event_type`: `'configured'`
- `source`: `'target'`
- `meta`: `jsonb_build_object('target_type', 'recurring', 'day_of_week', st.day_of_week)`

**Branch 4 — snipe_targets one_time:**
- Select from `snipe_targets st` where `user_id = $1`, `enabled = true`, `target_type = 'one_time'`, `target_date` within window.
- `event_date`: `st.target_date::text`
- `event_time`: `st.time`
- `event_type`: `'configured'`
- `source`: `'target'`
- `meta`: `jsonb_build_object('target_type', 'one_time')`

**ORDER BY:** `event_date, event_time NULLS LAST`

Use a CTE `WITH week_bounds AS (SELECT $2::date AS week_start, $2::date + INTERVAL '7 days' AS week_end)` to avoid repeating the date arithmetic.

4. **Response:** Return `NextResponse.json(rows)` — an array of `CalendarEvent`.

5. **Error handling:** Wrap the query in try/catch. On error, `console.error('[calendar] GET error:', err)` and return 500 `{ error: 'Internal server error' }`.

Follow the exact pattern from `dashboard/stats/route.ts` (session check outside try/catch, query inside try/catch).

Import `NextRequest` and `NextResponse` from `next/server`, `getSession` from `@/lib/cognito`, `query` from `@/lib/db`. Type the SQL result as `CalendarEvent` from `@fitness-sniper/shared`.

**Note on deduplication (from RESEARCH.md):** Do NOT filter out `configured` targets that have matching `history` records. Return all rows and let Phase 3 calendar UI handle priority logic (booked > pending > configured). This keeps Phase 2 simple.
