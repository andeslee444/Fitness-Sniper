**use-snipe-mutation.ts** — Create `web/src/hooks/use-snipe-mutation.ts`:

- Import `useMutation`, `useQueryClient` from `@tanstack/react-query`.
- Import `QUERY_KEYS` from `@/lib/query-keys`.
- Import `toast` from `sonner`.
- Define `SnipePayload` interface matching POST /api/targets fields:
  ```typescript
  interface SnipePayload {
    target_type: 'recurring' | 'one_time';
    studio_slug: string;
    location_id: string;
    time: string | null;
    class_type: string | null;
    seat_preference: string;
    preferred_spots: string[];
    target_date?: string;
    day_of_week?: number;
  }
  ```
- Export `useSnipeMutation(onSuccess?: () => void)` function:
  - Get `queryClient` via `useQueryClient()`.
  - Return `useMutation({...})` with:
    - `mutationFn`: `async (payload: SnipePayload)` — POST to `/api/targets` with JSON body. If `!res.ok`, parse error JSON and `throw new Error(data.error || 'Failed to create snipe target')`. Return `res.json()`.
    - `onSuccess`: Invalidate ALL calendar queries with partial key match: `queryClient.invalidateQueries({ queryKey: ['calendar'] })`. Also invalidate targets: `queryClient.invalidateQueries({ queryKey: QUERY_KEYS.targets })`. Call `toast.success('Snipe target created')`. Call `onSuccess?.()`.
    - `onError`: `toast.error(err instanceof Error ? err.message : 'Failed to create snipe target')`.
  - Note: Use `['calendar']` (not `QUERY_KEYS.calendarWeek(weekStart)`) so ALL weeks are invalidated — important for recurring targets that affect multiple weeks.
